## 📌 DESCRIPTION

In this project, I performed hands-on implementation of Git version control concepts, focusing on repository management, branching strategies, and merge conflict resolution.

The task began with setting up a local Git repository and connecting it to GitHub for remote version control. A basic project file was created and committed to establish the initial state of the repository.

To simulate real-world development scenarios, multiple branches were created, namely `feature1` and `feature2`. These branches represent parallel development workflows where different features or changes are developed independently.

Each branch introduced changes to the same file (`file.txt`) in the same section, which intentionally created a merge conflict scenario. This is a common situation in collaborative environments where multiple developers modify the same part of the codebase.

The branches were then merged back into the main branch. During this process, Git detected conflicting changes and marked them within the file using conflict markers.

The conflict was manually resolved by analyzing both changes and combining them appropriately. After resolving the conflict, the changes were staged and committed, completing the merge process successfully.

This task demonstrates a clear understanding of Git workflows, including branching, merging, and conflict resolution, which are essential skills in modern software development and DevOps practices.
